# 记录模板（JSON）—— 怎么改

> 这是**内容**，不是数据。所以模板放 JSON 文件、**不进数据库** —— 你随时可以用记事本/VS Code 改，
> 改完重启后端（或 App 重新构建）就生效。**不需要动代码、不需要迁移。**

## 目录结构

```
templates/
├── schema.json           ← 格式定义（说明字段能怎么写，程序不读它，是给你看的）
├── disciplines.json      ← 四大类 + 各类的「本次训练项目」清单
├── PT/                   ← 运动（58 项疗法）
│   ├── initial.json      ← 首评（该大类第 1 次治疗，强制）
│   ├── daily.json        ← 日常治疗记录
│   ├── reassessment.json ← 阶段性复评（每 20 次后自动触发）
│   └── discharge.json    ← 出院小结
├── OT/                   ← 生活技能（5 项疗法）
├── ST_SW/                ← 吞咽（4 项疗法）
└── ST_SP/                ← 言语（13 项疗法）
```

**四类 × 四形态 = 16 份，已全部完成。**

字段与选项取自你 2026-10-05 提供的模板：
`模块1 PT运动` / `模块2 OT日常生活技能（ADL）` / `模块3 吞咽功能` / `模块4 言语功能`
的 1.1–1.4 / 2.1–2.4 / 3.1–3.4 / 4.1–4.4 各节。

> 「本次训练项目」的候选值来自 `disciplines.json` 的 `therapy_options`
> （运动 58 / 生活技能 5 / 吞咽 4 / 言语 13），模板里用
> `"options_source": "therapy_options"` 引用，所以改清单只需改一处。

## ⚠ 评估文书**不占**日常训练次数

用户 2026-10-05 纠正：「评定并不占用日常训练的次数，比如第一次首评后，当天还是要有一个
日常记录用来记录当天的训练。复评和出院小结也是。」

| 形态 | 计入次数？ | 说明 |
|---|---|---|
| `initial` 首评 | **否** | 独立文书 |
| `daily` 日常记录 | **是** | 唯一计数的形态 |
| `reassessment` 复评 | **否** | 独立文书 |
| `discharge` 出院小结 | **否** | 独立文书 |

所以**同一天可能有两份文书**：

| 场景 | 产生 | 日常序号 |
|---|---|---|
| 第 1 天 | **首评 + 日常记录** | 日常记录 = 第 **1** 次 |
| 第 21 天 | **复评 + 日常记录** | 日常记录 = 第 **21** 次 |
| 出院当天 | **出院小结 + 当天日常记录** | 照常计数 |

**复评由「日常次数」触发**：日常满 20 次后（即第 21、41、61… 次日常）需要复评。

> 因此**评估文书不显示序号** —— 否则「出院小结 第 21 次」会被误读成第 21 次治疗记录。
> 出院小结改显示「共治疗 N 次」。

## ⚠ 三份评估文书都是**硬阻断**，不能跳过

用户 2026-10-05：「1A。2不能。3不能。」

**点一个大类后的流程**：先弹评估文书（如果需要）→ 填完 → **再填当天的日常记录**。

| 第 N 次日常 | 先必须完成 | 跳过会怎样 |
|---|---|---|
| 第 1 次 | **首评**（序号 1） | 不让记日常 |
| 第 2–20 次 | —— | 直接记日常 |
| 第 21 次 | **复评**（序号 21） | 不让记日常 |
| 第 22–40 次 | —— | 直接记日常 |
| 第 41 次 | **复评**（序号 41） | 不让记日常 |
| 出院时 | **出院小结** | 不让出院 |

**实现方式**：评估文书与它对应的日常记录**绑定在同一个序号**上
（首评挂 1、复评挂 21/41/61…），所以「本序号有没有这份文书」就是一个简单查询，
不需要额外的状态字段。规则实现在 `record_template.py`：

- `assessment_span_seq(seq_no)` → 该日常序号对应的评估区间标识
- `next_session_gate(next_seq, has_initial=…, reassessment_spans=…)` → 还缺哪份文书
  （`None` = 可以记）

**App 与后端都调这两个函数**，避免两边各写一遍判定逻辑而漂移。

## 四种字段类型

| 类型 | 用途 | 输出成什么 |
|---|---|---|
| `single` | 单选（模板里的「清晰/嗜睡/意识模糊」） | 选中的那一项 |
| `multi` | 多选（「本次训练项目」） | 选中的项用 `/` 连接 |
| `number` | 数值填空（「疼痛VAS：__分」） | 数字 + `unit` |
| `text` | 自由文字 | 原样 |

例：

```json
{ "key": "vas", "type": "number", "label": "疼痛VAS", "unit": "分" }
{ "key": "consciousness", "type": "single", "label": "神志",
  "options": ["清楚", "嗜睡", "意识模糊"] }
{ "key": "therapy_items", "type": "multi", "label": "本次训练项目",
  "options_source": "therapy_options", "required": true }
```

> `"options_source": "therapy_options"` 表示 **选项取自 `disciplines.json` 里该大类的清单** ——
> 这样改疗法清单只需改一处，不用动 4 份模板。

## 改的时候要注意 5 件事

### 1. ⚠ 首评与复评的「客观资料」字段必须用**同一套 `key`**

这是**出院小结能自动汇总**「下肢肌力 2级→3级」的前提。

改 `PT/initial.json` 里 O 段的某个 `key`，**必须同步改** `PT/reassessment.json` 和 `PT/discharge.json`。
改漏了不会报错，但出院小结的功能变化会**静默少一项**。

（`scripts/preview_record_templates.py` 会检查这条，改完跑一下它。）

### 2. 排版是统一的，不用配（原先的 `inline` 已弃用）

**所有形态**（首评/日常/复评/出院）都是同一套排版：

```
主观资料：精神状态：良好；主诉：乏力；疼痛VAS：2分；训练配合度：良好

客观资料：本次训练项目：偏瘫肢体综合训练/平衡功能训练；维持站立时间：45s
```

段首是**中文段名 + 冒号**，段内字段用 `；` 连接，字段值内部的多选用 `/` 连接。
**没填的字段整条不出现。**

> 用户 2026-10-05：『A 形式是正确的，其他的记录也要这样。
> 多日的情况下，是按时间顺序往下排就行，不用一天一张。』
> 所以模板里**不要再写 `inline`** —— 渲染器已固定为这种排版。

### 3. 必填要克制

`"required": true` 只给真正关键的项（现在是「功能诊断」和「本次训练项目」）。
**必填项加太多会拖慢床旁录入** —— 而这正是这次重构要解决的问题。

### 4. 预填策略（`prefill`）

| 值 | 含义 |
|---|---|
| `last_assessment` | 带出该大类**上一次的评估值**（首评或上次复评）—— 复评/出院用，治疗师只改变化的项 |
| `last_daily` | 带出上次的「本次训练项目」—— 日常记录**只**预填这一项 |
| `same_day_first` | 带出**同一天同大类第 1 条**的内容 —— 同一天第 2 条自动预填 |

> 日常记录**故意不预填**「自觉症状/疼痛VAS/配合度」这些 —— 它们每天都该**重新判断**，
> 预填会变成「顺手不改」的假数据，损害病历质量。

### 5. 签名不采集

`footer` 里只有 `治疗师签名：__________` 占位符。**签名与时长由独立签字系统承担**，本系统不做。

### 6. 选填备注（`extra_note`）

四份模板最后都有一项选填备注：

```json
{ "key": "extra_note", "type": "text", "label": "备注",
  "hint": "选填。留空则记录里不显示这一项。" }
```

**留空时输出里完全不出现**（`备注` 这两字也不出现）—— 这是渲染器的通用规则：
没填的字段整条不出现，所以你可以照这个模式加任何选填项。

> ⚠ `key` **不能与 `label` 同名**。渲染是 `label：值`，同名会输出「**备注：备注：**…」。
> 所以 key 用 `extra_note`、label 用 `备注`。

## 改完怎么验证

```powershell
cd backend
C:\Users\youda\AppData\Local\Programs\Python\Python313\python.exe scripts\preview_record_templates.py
```

它会：
1. 校验 16 份模板的结构（SOAP 段齐不齐、key 重不重、选项空不空）
2. 检查**首评与复评的 O 段共用多少 key**（太少会报失败 —— 出院小结汇总不了）
3. 打印触发规则（第 1 次→首评、第 21 次→复评…）
4. **把四种形态实际渲染出来给你看**（用示例数据）
